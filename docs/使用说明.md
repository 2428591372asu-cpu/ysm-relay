# ysm-relay 使用说明

> 给玩家和服主看的。技术细节在 [02-YSM3.0接入点调研.md](02-YSM3.0接入点调研.md)，服主命令清单在 [ADMIN.md](ADMIN.md)。

## 这个 mod 解决什么

YSM（Yes Steve Model）原来的模型分发是**单向**的：服务端放什么，客户端就能拿到什么。玩家想用自己的模型，得先找到服主，把文件发过去，等服主丢进目录，再等服务器重扫。全程要人。

ysm-relay 补上**反向的那一段**：

```
玩家客户端 ──上传模型──> 服务端落盘 ──> YSM 自己重扫 ──> 自动分发给所有客户端
```

服务端一旦收到，YSM 原生的分发链路就会把它接进去，其他玩家下次打开模型列表就能看见，**不需要重启服务器**。

另外补了服主侧的管理面：看谁传了什么、删掉不要的、限制单模型大小、按玩家控制哪个模型能用。

---

## 安装

| 位置 | 需要装 |
| --- | --- |
| 服务端 | `ysm` 3.x + `ysm_relay` |
| 客户端 | `ysm` 3.x + `ysm_relay` |

两边都要装 relay，否则上传通道不存在，玩家无法上传（但仍能正常用服主投放的模型）。

> **重要**：relay 是 YSM 的附属 mod，YSM 不在时它会自动停用并只打日志，不会让服务器启动失败。

## 玩家：怎么上传

### 方法一：面板（推荐）

游戏内按快捷键打开上传面板，选中本机的模型文件，点上传。面板会显示进度和结果。

### 方法二：命令

```
/ysmrelay upload <本机模型文件路径>
/ysmrelay status      # 看当前进度
/ysmrelay cancel      # 取消
```

路径要写本机的绝对路径，例如：

```
/ysmrelay upload D:\models\my_model.ysm
```

路径带空格时用引号包起来：

```
/ysmrelay upload "D:\my models\cute fox.ysm"
```

### 支持的格式

`.mxc`、`.ysm`、`.zip`、`.7z`，以及含 `ysm.json` / `main.json` 的模型目录（目录型目前只能靠服主手动放）。

旧版加密的 `.ysm`（V3）会被拒绝。

### 上传时会发生什么

1. 客户端先算这个模型的**内容标识**（不是文件名、不是文件大小 —— 是模型内容的哈希）
2. 把这个标识发给服务端，问「你要不要」
3. 服务端查目录：
   - **已经有同一个模型** → 直接回「不用传」，**一个字节都不发**
   - 超过服主设的大小上限 → 当场拒绝
   - 服主关掉了上传 / 删过这个模型 → 拒绝
   - 都没有 → 允许，开始分块传
4. 服务端收完、校验、规范化成 YSM 的容器格式，落进模型目录
5. 触发一次重扫，新的模型出现在所有人的列表里

第 3 步是关键：**重复的模型永远不占带宽**。同一个模型十个人传，磁盘上只有一份。

## 服主：配置

配置文件在 `config/ysm-relay-server.toml`。

```toml
[upload]
# 允许玩家上传。关掉后只有你能放模型。
allowPlayerUpload = true

# 单个模型的大小上限，字节。0 = 不限。
# 默认 64 MiB。
maxModelBytes = 67108864

# 服务端要求客户端用的分片大小。一般不用动。
chunkBytes = 32768

# 未完成的上传在暂存区保留多久（秒），超时自动清理。
stagingTtlSeconds = 600

# 需要多少权限等级才能上传。0 = 任何玩家。
uploadPermissionLevel = 0

# 上传落到哪个目录根：
#   custom = 人人可见
#   auth   = 只有被授权的玩家能选（上传者本人会自动拿到授权）
targetRoot = "custom"
```

## 服主：管理命令

全部需要权限等级 2（与 YSM 自己的 `/ysm` 对齐）。

```
/ysmrelay status              总览：模型数、授权策略数、上传落点
/ysmrelay list [页]           列出授权策略
/ysmrelay show <玩家>         看某玩家当前持有哪些授权
/ysmrelay policy <模型> ...   设置授权策略（public / listed / except）
/ysmrelay grant <玩家> <模型>
/ysmrelay revoke <玩家> <模型>
/ysmrelay move <模型> auth|custom
/ysmrelay delete <模型> confirm
/ysmrelay block <模型>        禁止再次上传
/ysmrelay unblock <模型>
/ysmrelay refresh [玩家]      按策略重推授权
```

模型参数可以写完整 64 位哈希、8 位以上的哈希前缀，或 `local:auth/xxx.mxc` 这样的公开地址。

### 删除的坑（已处理）

`/ysmrelay delete` 会做三件事，顺序不能换：

1. 撤掉所有在线玩家对这个模型的授权
2. 删磁盘文件 + 重扫
3. **把这个模型加进「禁止上传」名单**

第 3 步是必需的。不加的话，玩家下次传同一个模型，服务端查目录发现「没有」就放行了 —— 文件原样回来，删除等于没删。上传通道的探测阶段会查这张名单。

## 数据文件在哪

| 文件 | 内容 |
| --- | --- |
| `config/ysm-relay-server.toml` | 上传配置 |
| `config/ysm-relay/authz.json` | 授权矩阵（谁对哪个模型有策略） |
| `config/ysm-relay/uploads.json` | 上传台账（谁传了什么、多大、什么时候） |

暂存目录在模型根的同级 `relay-staging/` 下，**不在模型根里**（避免被 YSM 扫描）。

## 已知限制

**1. 目录型模型不支持上传**
协议只收文件。含 `ysm.json` 的模型目录要服主手动放。

**2. 迁根会改模型的地址**
`/ysmrelay move` 会把模型从 `custom` 搬到 `auth`（或反过来），它的公开地址会跟着变。如果你在 YSM 的 `DefaultModelPath` 里引用过这个地址，搬完要跟着改。

**3. 文件被占用时删不掉**
Windows 上 YSM 可能还持有模型文件的句柄，这时删除和搬迁会失败并**明确报错**（不会假装成功）。先重启服务端再操作。

**4. 「某玩家不能用某模型」= 白名单的反向写法**
YSM 只有白名单（`canSelect = public 或 已授权`），没有「禁止某人用某模型」的黑名单。所以这个功能是靠：

- 模型放 `auth` 根（变成「需要授权才能选」）
- 用 `policy ... except <玩家>` 给「除他以外所有人」授权

代价是这类模型必须是「默认全员 + 排除名单」模式，新玩家第一次进服时由登录事件补授权。

**5. 网络层用的是 relay 自己的通道**
不占用、也不修改 YSM 的协议。两边版本不一致时会互相拒绝（用 `acceptMissingOr` 策略，只装了服务端的客户端不会被踢出服务器，只是用不了上传）。

## 当前验证状态（诚实说明）

- **编译**：`gradlew compileJava` 通过，零错误。
- **运行验证**：**未完成**。开发机上没有 `ysm.dll`（YSM 的 native 库），而 YSM 连读一个目录里的模型文件都要用它（`Directory.getFile → NativeHeapBuffer.nAlloc`）。没有 native 连模型标识都算不出来，所以「上传 → 落盘 → 重扫 → 分发」这条链目前是**编译过、没跑过**。

要补上这一步，需要满足其一：

1. 一个含 native 的 YSM 3.x 发布版 jar（放进 `mods/` 即可）
2. 单独提供 `ysm.dll`，在 YSM 的 `local.properties` 里设 `ysm.native_path`
3. 用 `ysm-native` 工程本地编译出 `ysm.dll`（整理前该目录叫 `YesSteveModel-Native`；此路 2026-11-04 已不需要 —— YSM 3.0 的运行 jar 内已内嵌 `META-INF/native/ysm.dll`，提取版在 `YSM/native/ysm.dll`）

拿到之后，`build/selftest/ModelIdentitySelfTest.java` 改两行就能直接验证最底层的那条假设：

```
客户端 scanModelHash 算出的 modelId  ==  服务端 capture 的 modelId  ==  convert 产出的 modelHash
```

三者不一致的话，去重和导入校验都会失效 —— 这是整条链的地基，它不对，上面全废。
